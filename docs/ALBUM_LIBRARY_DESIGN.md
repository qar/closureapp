# Closure 专辑曲库功能设计

状态：草案

日期：2026-08-19

本文只描述“专辑列表、添加专辑和专辑封面”功能的产品与架构设计，不包含代码实现。实现前应先根据本文的待确认事项完成一次设计确认。

## 1. 已确认的产品方向

| 项目 | 决定 |
| --- | --- |
| 专辑来源 | 用户选择一个文件夹导入为一个专辑 |
| 专辑与播放列表 | 专辑库独立于当前播放列表 |
| 封面 | 默认使用歌曲内嵌封面，并支持自定义封面覆盖 |
| 专辑浏览 | 封面网格，点击进入专辑详情 |
| 播放专辑 | 替换当前播放队列，并立即从第一首开始播放 |
| 现有播放列表 | 保持原样，不在启动时自动转换为专辑 |
| 音乐文件 | 继续引用用户原文件，不复制或移动音乐文件 |

## 2. 当前实现基线

当前版本已经具备部分可复用能力，但还没有独立曲库。

- `TrackMetadata` 已包含 `album`、`albumArtist` 和内嵌 `artwork` 字段，见 `src/audio/TrackMetadata.h`。
- `TrackMetadataReader` 已能异步读取标题、艺术家、专辑、时长和 macOS 音频元数据中的封面，见 `src/audio/TrackMetadataReader.mm`。
- `AudioEngine` 当前负责设备、传输、播放队列、元数据缓存和播放列表路径持久化，见 `src/audio/AudioEngine.cpp`。
- `GaplessPlaylistSource` 只管理按文件路径排列的扁平播放队列，见 `src/audio/GaplessPlaylistSource.cpp`。
- `PlayerPanel` 当前是单页布局，左侧显示当前播放，右侧使用 `ListBox` 显示播放列表，底部显示播放控制，见 `src/ui/PlayerPanel.cpp`。
- 当前持久化内容只有 `playlistPaths`，没有专辑实体、曲目号、专辑封面缓存或专辑编辑信息。
- `docs/VISION.md` 已经预留后续 `Library / Cloud adapters`，专辑曲库应作为本地曲库模块落在这一层，而不是塞进音频播放模块。

## 3. 目标与非目标

### 3.1 目标

- 用户可以从一个本地文件夹创建专辑。
- 用户可以在专辑网格中浏览专辑名称、艺术家、曲目数和封面。
- 用户可以打开专辑详情，查看有序曲目。
- 用户可以播放整张专辑，或将专辑加入当前队列。
- 用户可以编辑专辑名称、艺术家和封面。
- 专辑在应用重启后仍然存在。
- 音乐文件丢失时，专辑仍然保留，并能明确显示不可用曲目。
- 专辑播放与现有 gapless、重复模式和进度控制兼容。

### 3.2 非目标

- 不扫描整个 Music 目录。
- 不自动把所有已有音乐按标签归类成专辑。
- 不复制、移动或重新编码用户的音乐文件。
- 不实现在线封面抓取或在线元数据服务。
- 不在第一阶段实现云同步。
- 不把专辑业务逻辑放入 `GaplessPlaylistSource`。

## 4. 领域术语

### 专辑 Album

用户在曲库中保存的独立集合。专辑有稳定身份、名称、艺术家、封面和有序曲目列表。专辑不等同于当前播放队列。

### 曲目 Track

专辑中的一首音乐。曲目由原始文件路径引用，并保存播放顺序和必要的展示元数据。

### 播放队列 Queue

播放器当前要播放的扁平曲目序列。播放队列可以由专辑生成，也可以继续由现有的 `Add music` 功能直接生成。

### 曲库 Library

持久化保存专辑和曲目引用的本地模块。曲库负责专辑管理，不负责音频设备和实时播放。

### 封面 Cover

专辑级别的展示图片。封面可以来自歌曲内嵌图片，也可以来自用户选择的自定义图片。

## 5. 用户流程

### 5.1 添加专辑

```text
点击 Add album
    ↓
选择一个文件夹
    ↓
递归扫描支持的音频文件
    ↓
读取曲目元数据
    ↓
生成专辑草稿
    ↓
确定名称、艺术家和封面
    ↓
保存专辑到曲库
    ↓
专辑出现在封面网格
```

具体规则：

1. 选择的文件夹默认代表一张专辑。
2. 扫描支持当前已有的本地音频格式。
3. 不存在、不支持或无法创建解码器的文件不会进入曲目列表。
4. 专辑名称默认取文件夹名；如果扫描出的曲目拥有一致的 `album` 标签，可以将其作为更优默认值。
5. 艺术家默认取 `albumArtist`，其次取曲目艺术家；没有信息时使用 `Unknown Artist`。
6. 曲目按 `discNumber`、`trackNumber`、文件路径排序；缺少曲目号时回退到文件路径排序。
7. 添加专辑只保存到曲库，不自动改变当前播放状态。
8. 保存前应展示扫描结果和草稿预览，让用户确认或修改专辑名称、艺术家和封面。

### 5.2 选择封面

封面选择优先级如下：

```text
用户自定义封面
    ↓
曲目内嵌封面
    ↓
自动生成的占位封面
```

默认从按曲序排列的曲目中选择第一张有效内嵌封面。如果多首歌曲的内嵌封面不一致，仍使用第一张，并在编辑专辑时允许用户覆盖。

自定义封面应由应用复制到自己的应用数据目录，并在曲库中保存副本路径。应用不应只依赖用户选择的原始图片路径。

### 5.3 浏览和播放专辑

专辑页面显示封面卡片。点击卡片进入详情页，详情页显示：

- 大尺寸封面
- 专辑名称
- 艺术家
- 曲目数量
- `Play album` 操作
- `Add to queue` 操作
- 有序曲目列表

点击 `Play album` 时：

1. 曲库返回该专辑中当前存在的曲目路径，并保持专辑顺序。
2. 播放模块一次性替换当前播放队列。
3. 播放模块选择第一首并立即开始播放。
4. 现有重复模式、gapless 播放、进度和上一首/下一首继续由 `AudioEngine` 处理。

`Add to queue` 是非破坏性操作，将专辑曲目追加到现有队列，不改变当前正在播放的曲目。

### 5.4 编辑和移除专辑

用户可以编辑：

- 专辑名称
- 艺术家
- 自定义封面

移除专辑只移除曲库记录和应用管理的封面缓存，不删除原始音乐文件。

## 6. UI 设计

### 6.1 页面结构

保留当前布局的三个主要区域：

```text
┌──────────────────────────────────────────┐
│ CLOSURE                 Add music Add album│
├────────────────┬─────────────────────────┤
│ 当前播放        │ Albums | Queue           │
│                 │ 专辑网格或队列列表       │
├────────────────┴─────────────────────────┤
│ 进度、播放控制、音量                        │
└──────────────────────────────────────────┘
```

当前播放区和底部播放控制继续复用现有 `PlayerPanel` 能力。右侧内容区增加 `Albums` 和 `Queue` 两个视图。

### 6.2 专辑卡片

每张卡片显示：

- 封面
- 专辑名称
- 艺术家
- 曲目数量

没有封面时使用稳定的占位颜色和图形，颜色由专辑 ID 或来源路径生成，避免每次启动发生变化。

### 6.3 专辑详情

专辑详情可以先复用当前右侧播放列表区域，不要求第一阶段引入独立窗口。详情页的曲目列表应显示：

- 曲目序号
- 曲目标题
- 艺术家
- 时长
- 文件不可用标记

点击详情中的单曲时，可以只播放该曲目，也可以保持专辑队列上下文。该行为需要在实现前确定，建议默认播放整张专辑并将该曲目作为起始曲目。

## 7. 数据模型

建议使用稳定 ID，而不是用专辑名称作为身份。名称和艺术家可以修改，ID 不随之变化。

```text
AlbumRecord
    id: string
    title: string
    artist: string
    sourceFolder: string
    tracks: TrackRecord[]
    cover: CoverRecord
    createdAt: timestamp
    updatedAt: timestamp

TrackRecord
    path: string
    title: string
    artist: string
    discNumber: integer?
    trackNumber: integer?
    durationSeconds: number

CoverRecord
    mode: embedded | custom | placeholder
    cachedPath: string?
```

曲目路径是外部文件引用。曲目元数据可以在导入时保存快照，也可以在启动时重新读取；建议保存展示快照，同时在文件变化时允许重新扫描。

同一个原始音乐文件是否允许出现在多个专辑中，目前建议允许。这样可以表达合辑或用户自定义整理，曲库不应把文件路径错误地当成全局唯一的专辑成员关系。

## 8. 持久化和文件生命周期

### 8.1 曲库文件

建议新增独立的版本化曲库文件：

```text
Application Support/Closure/library.xml
```

文件保存：

- 曲库格式版本
- 专辑 ID 和基础信息
- 来源文件夹
- 曲目路径和曲目顺序
- 用户编辑后的名称和艺术家
- 自定义封面缓存路径

不建议把完整图片二进制直接写入设置文件。内嵌封面和自定义封面都可以生成应用管理的缩略图，专辑列表优先加载缩略图。

现有的 `playlistPaths` 继续作为当前播放队列快照保存，不与专辑数据混合。

### 8.2 应用重启

```text
读取 library.xml
    ↓
恢复专辑记录
    ↓
检查曲目路径
    ↓
标记缺失曲目
    ↓
异步加载封面和元数据
    ↓
显示专辑列表
```

文件不存在时不应直接删除曲目记录。专辑保留并显示不可用状态，方便用户以后重新连接外置磁盘或执行重新定位。

第一阶段可以只支持“标记不可用”，不实现自动重新定位。重新定位可以作为后续功能。

## 9. 模块边界

### `MusicLibrary` 模块

负责：

- 添加和移除专辑
- 扫描目录
- 读取和整理曲目元数据
- 维护专辑顺序
- 管理专辑封面
- 读写曲库文件
- 标记缺失文件
- 提供专辑列表和详情快照

不负责音频设备、播放线程和实时播放状态。

### `AudioEngine` 模块

继续负责：

- 音频设备初始化
- 解码播放
- 播放队列
- gapless 播放
- 重复模式
- 进度、音量和播放状态

需要增加一个语义明确的“替换队列并播放”操作，避免 UI 自己组合 `clearPlaylist()`、`addFiles()` 和 `play()`。

### UI 模块

建议增加一个专辑浏览模块，负责：

- 专辑网格
- 专辑详情
- 添加专辑对话框
- 编辑专辑对话框
- 播放和入队操作

UI 不应直接读写曲库文件，也不应直接操作封面缓存路径。

### 状态回调

专辑列表使用独立的曲库状态回调。不要把完整专辑列表和封面加入 `AudioEngine::State`，因为当前播放位置会高频触发 `notifyState()`，专辑数据不应随每个音频进度刷新。

## 10. 错误和边界行为

| 场景 | 处理方式 |
| --- | --- |
| 文件夹不存在 | 不创建专辑，显示错误信息 |
| 文件夹没有支持的音频 | 不创建专辑，提示没有可用曲目 |
| 单个文件无法解码 | 跳过该文件，并在预览中显示警告 |
| 文件重复导入 | 按来源目录或曲目路径集合检测，提示用户跳过或更新 |
| 专辑封面读取失败 | 回退到占位封面 |
| 原始音乐文件被移动 | 保留曲目记录并标记不可用 |
| 原始音乐文件被删除 | 保留曲目记录并标记不可用 |
| 自定义封面被删除 | 回退到内嵌封面或占位封面 |
| 删除专辑 | 不删除音乐文件，只删除曲库记录和应用管理的封面缓存 |
| 添加专辑过程中取消 | 丢弃草稿，不改变曲库和当前播放状态 |

导入结果应向用户报告成功、跳过和失败数量。不能像当前 `addFiles()` 一样只返回数量并静默忽略失败。

## 11. 现有数据迁移

当前播放列表不应在启动时被静默转换为专辑，原因是：

- 播放列表可能包含多个专辑。
- 无标签歌曲会被错误合并。
- 同名专辑可能来自不同艺术家。
- 用户没有明确表达要建立曲库。

第一阶段保持现有 `playlistPaths` 行为不变。后续如果需要迁移，可以增加显式操作“从当前播放列表创建专辑”，由用户确认分组结果后再保存。

## 12. 测试设计

### 曲库模块测试

- 导入包含有效和无效文件的目录。
- 空目录不能创建专辑。
- 曲目排序正确处理碟号和曲目号。
- 缺少曲目号时按文件路径排序。
- 专辑名称和艺术家默认值正确。
- 自定义封面覆盖内嵌封面。
- 没有封面时生成稳定占位状态。
- 曲库保存后重新加载结果一致。
- 缺失文件保留并标记不可用。
- 重复导入行为符合定义。
- 删除专辑不会删除音乐文件。

### 播放衔接测试

- 播放专辑会按照曲库顺序生成扁平队列。
- 播放专辑会替换原队列。
- 播放专辑会自动开始第一首。
- 专辑播放继续支持 gapless。
- 专辑播放继续支持单曲循环、列表循环和关闭循环。
- 专辑中有缺失文件时不会把无效路径交给播放器。

### UI 验收测试

- 添加专辑后，专辑卡片立即出现占位封面或真实封面。
- 异步元数据和封面完成后，卡片和详情正确刷新。
- 添加专辑不会打断当前歌曲。
- 播放专辑会刷新当前播放区域和队列。
- 删除专辑不会删除磁盘上的音乐文件。
- 窄窗口下专辑网格和详情仍可操作。

## 13. 建议的实现阶段

### 阶段一：曲库基础

- 定义 `AlbumRecord`、`TrackRecord` 和曲库状态。
- 新增曲库持久化。
- 实现选择目录、扫描文件和创建专辑。
- 实现专辑列表状态回调。

### 阶段二：封面和详情

- 补充专辑艺术家、碟号和曲目号读取。
- 实现内嵌封面选择。
- 实现自定义封面和封面缓存。
- 实现专辑网格和专辑详情页。

### 阶段三：播放衔接

- 增加“替换队列并播放”接口。
- 增加“加入队列”接口。
- 验证专辑顺序、重复模式和 gapless 行为。

### 阶段四：编辑和异常状态

- 编辑专辑名称、艺术家和封面。
- 缺失文件提示。
- 重复导入处理。
- 曲库和封面缓存清理。

## 14. 待确认事项

以下事项不阻塞当前设计，但实现前需要确定：

1. 是否递归扫描选中的文件夹，包括多碟专辑子目录。当前建议递归扫描。
2. 文件夹内实际包含多个不同专辑时，是否仍作为一个专辑。当前产品决定是“一个文件夹一个专辑”，建议在预览中显示警告而不是自动拆分。
3. 点击专辑详情中的单曲时，是播放整张专辑并从该曲开始，还是只播放该曲。当前建议保留专辑上下文，从选中曲开始播放。
4. 重复导入同一来源目录时，是拒绝、更新已有专辑，还是创建副本。当前建议提示用户选择。
5. 是否在第一阶段提供“重新定位丢失文件”。当前建议先只显示不可用状态。
